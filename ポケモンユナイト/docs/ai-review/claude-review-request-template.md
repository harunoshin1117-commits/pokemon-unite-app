# Claude Review Request Templates

このファイルは、Claude無料版へ貼る依頼文のテンプレートです。`scripts/create-claude-review-pack.js` は、このテンプレートと `claude-review-context.md`、git diff要約を組み合わせて `generated/claude-review-request.md` を生成します。

## 用途A: API設計・データ構造相談

```md
あなたには、実装担当ではなく外部レビュー担当・設計相談相手として見てほしいです。
コードは書かず、設計レビューだけしてください。

相談したい内容:
- [ここに相談したいAPI、データ構造、責務分離案を書く]

特に見てほしい観点:
1. この設計は自然か。
2. `battleState` / `pokemonData` / `damageCalculator` の責務分離が崩れていないか。
3. 将来ほかのポケモンや特殊効果を追加したとき破綻しないか。
4. 例外処理が増えすぎる設計になっていないか。
5. 未確認仕様を確定実装へ入れる構造になっていないか。
6. 今すぐ直すべき点と後回しでよい点を分けてほしい。

回答形式:
1. 総評
2. 良い点
3. 今すぐ直すべき点
4. 後回しでよい点
5. 代替案
6. Codexに修正依頼するならこう頼む
```

## 用途B: Codex変更・PRレビュー

```md
あなたには、実装担当ではなく外部レビュー担当として見てほしいです。
Claude側で追加実装はしないでください。レビューだけしてください。

レビュー対象:
- Codexが作った変更、PR、またはgit diff要約

特に見てほしい観点:
1. Codexの変更がやりすぎていないか。
2. 既存方針に反していないか。
3. 責務分離が崩れていないか。
4. データ構造や命名が自然か。
5. 未確認仕様を確定扱いしていないか。
6. 既存機能を壊す可能性がないか。
7. テストが実装内容を追認するだけになっていないか。
8. 今すぐ修正すべき点、後でよい点、問題ない点に分けてほしい。

回答形式:
1. 重大な問題
2. 中程度の問題
3. 軽微な改善点
4. 問題ない点・良かった点
5. 不明点・人間確認が必要な点
6. 総合判断
```

## 用途C: UI/UXレビュー

```md
これはポケモンユナイトのダメージ計算サイトの画面です。
このスクリーンショットを見て、UI/UX観点でレビューしてください。

前提:
- ユーザーは主にスマホで使う想定です。
- ユーザーは攻撃側ポケモン、防御側ポケモン、レベル、技、持ち物などを選び、ダメージ結果を見る想定です。
- 今回は実装コードではなく、画面の分かりやすさと操作しやすさだけを見てください。
- Claude側で実装コードは書かないでください。

この画面でユーザーにやってほしい操作:
1. 攻撃側ポケモンを選ぶ
2. 防御側ポケモンを選ぶ
3. レベルや条件を選ぶ
4. 技または通常攻撃を選ぶ
5. ダメージ計算を実行する
6. 結果を確認する

ユーザーが追記する欄:
- 今回の画面名:
- 特に見てほしい箇所:
- 迷っている改善案:
- 想定端末や画面幅:

見てほしい観点:
- 初見で何をすればいいか分かるか。
- 情報量が多すぎないか。
- ボタン名、項目名、表示順が自然か。
- スマホで操作しやすいか。
- 攻撃側、防御側、技選択、結果表示の流れが分かりやすいか。
- 誤操作しそうな場所はあるか。
- 優先して直すべきUI問題はあるか。

回答形式:
1. 良い点
2. 迷いやすい点
3. 優先して直すべき点
4. 後回しでよい点
5. Codexに修正依頼するならこう頼む
```
