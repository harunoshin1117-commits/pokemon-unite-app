## プロジェクトの現在地

このプロジェクトは、ポケモンユナイトのダメージ計算サイトから、将来的に「ゲーム内の練習場で行う検証作業をブラウザ上で再現・記録・比較できる検証サイト」へ広げる方針です。

現在は、以下を重視しています。

- ゲーム内で実際に出るダメージをできるだけ再現する。
- 計算式だけでなく、処理順、丸め位置、HP参照タイミングも検証する。
- 未確認仕様を確定扱いせず、調査データに状態付きで残す。
- 実装データと研究用データを分ける。

## battleStateの現在地

`ポケモンユナイト/js/battleState.js` を追加し、現在は直近の計算結果 `lastCalculation` だけを管理しています。

- 攻撃後、通常攻撃・技1・技2・ユナイト技の計算済みデータを保存する。
- 全リセット時に `lastCalculation` を `null` へ戻す。

- `damageCalculator.js` からは参照しない。

まだ attacker / defender の現在HP、火種スタック、シールド、攻撃順は移行していません。

## データ駆動化の状況

### 通常攻撃

ピカチュウとエースバーンは、新しい `normalAttack` データ形式へ一部移行済みです。

- ピカチュウ
  - 通常攻撃: `attack` と `defense` を参照
  - 強化通常攻撃: `spAttack` と `spDefense` を参照

- エースバーン
  - 通常攻撃、強化通常攻撃ともに `attack` と `defense` を参照
  - 技使用後に次の通常攻撃が強化される仕様は、将来の攻撃順機能で扱う予定

ゲッコウガなどは、まだ全面移行していません。

### 技ダメージ

ピカチュウの一部技は `damageComponents` 形式へ移行中です。

- エレキネット
- エレキボール
- かみなり
- ボルテッカー
- 10万ボルト
- フルボルトストーム

エレキボールは、相手の減少HPを参照する追加ダメージを `additionalDamageEffects` で表現しています。

## エースバーン調査の現在地

現在、エースバーンを優先して検証しています。

主な理由:

- 通常攻撃
- 強化通常攻撃
- 技使用後の強化通常攻撃
- 火種スタック
- HP条件付きバフ
- 野生ポケモン上限
- 減少HP参照ダメージ
- ユナイト技の謎

など、将来の共通システムに必要な要素が多いためです。

### 特性「もうか」火種

現時点で確認済みまたは有力なもの:

- 通常攻撃で火種1個付与。
- 強化通常攻撃で火種2個付与。
- 技で火種2個付与。
- 火種5個到達で追加ダメージが発生。
- 発火時は5個だけ消費し、余剰スタックは残る。
- 発火後に1スタック残った想定で4スタック分の攻撃を行い、再発火を確認済み。
- 本体ダメージ表示後に火種追加ダメージが表示される方針。
- 火種追加ダメージは、本体急所とは独立している。
- ピカチュウLv15相手では、通常攻撃、強化通常攻撃、ニトロチャージ、火炎ボールのいずれでも火種追加ダメージは726。
- エースバーンLv15相手では683。
- ゲッコウガLv15相手では698。

未確定:

- 火種の再付与時に持続時間がどう更新されるか。
- 複数対象で完全に独立して保持されるか。
- 発火処理の内部順序が、本体ダメージ後で本当に確定か。
- 火種追加ダメージの厳密な丸め順。

### 火種の丸め・防御補正

ピカチュウLv13〜15では、以下の傾向があります。

```text
ピカチュウLv13〜15:
パーツ別防御補正で実測一致。
標準計算ではすべて+1ズレ。

ただし:
ゲッコウガでは標準計算が一致しているため、
火種全体の丸め仕様として確定するにはまだ不足。

判定:
measuredCandidate / unresolved
```

この内容は `データリサーチ/cinderace-researchData.json` に記録済みです。

### ユナイト技

`Blazing Bicycle Kick` は、Unite-DB の sourceFormula だけでは本体ダメージを再現できていません。

現在の整理:

- 本体式: `conflict / needsCorrection`
- 追加ダメージ式: `measuredCandidate`
- 追加ダメージの参照タイミング: `measuredCandidate`
- サイト再現用計算: measured main damage または measuredFormulaCandidate が必要

ただし、Unite-DB の式が間違っていると断定するのはまだ早いため、現時点では見送りです。
今後、大量のポケモンデータ整理後に再検証する方針です。

## AIに読ませるときの注意

- `ポケモンユナイト/docs/ai-workflow.md` を先に読む。
- 調査JSONは `データリサーチ/` にあるため、アプリ本体の `ポケモンユナイト/` だけを読んで判断しない。
- `candidate`、`measuredCandidate`、`unresolved` を確定扱いしない。
- アプリ本体に反映済みの情報と、調査中の情報を分ける。
- 計算結果を変える提案では、どの実測値と照合したかを必ず確認する。
